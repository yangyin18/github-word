## 1. Выбор технологии
### 1.1 Обзор выбора
| Уровень | Технология | Причина выбора |
|---|---|---|
| Фреймворк сервера | Python 3.11 + FastAPI | Нативная асинхронная поддержка, подходит для I/O-интенсивных задач (GitHub API + параллельные вызовы переводных движков); автоматически генерирует OpenAPI документацию |
| Фреймворк клиентского интерфейса | Vue 3 + Vite + TypeScript | Связь данных с откликом подходит для сравнения переводов и редактирования по частям; быстрое построение с Vite |
| Библиотека компонентов UI | Element Plus | Полные по-русски документы, богатый набор компонентов (таблицы, диалоги, редакторы) |
| Парсинг Markdown | `markdown-it-py` (сервер) / `marked` (предварительный просмотр клиентского интерфейса) | Используется для разделения на части на сервере, а также для предварительного просмотра перевода в клиентском интерфейсе |
| Система управления базами данных | SQLite (разработка) / PostgreSQL (производство) | Нулевая настройка для разработки; для производства можно легко перенести |
| Кэширование | Redis (опционально) | Кэширование результатов перевода, подсчет ограничений скорости |
| Клиент HTTP | `httpx` (асинхронный) | Асинхронные вызовы GitHub API и переводных движков |
| GitHub API | REST API v3 + `httpx` | Прямой вызов, не требует дополнительной зависимости; ресурсы без токена доступны (при более лояльных ограничениях скорости можно использовать токен) |
| Переводные движки | Абстрактный интерфейс + несколько реализаций (Mock / Google / DeepL) | Разделение зависимостей, облегчает переключение и тестирование |
| Очередь задач | FastAPI BackgroundTasks (P0) / Celery + Redis (P1+) | Для P0 достаточно заданий в фоне; для P1 PR требуется постоянная очередь |
### 1.2 Переводные движки абстрактные
Определение единого интерфейса, поддерживающего несколько реализаций:
# app/services/translator/base.py
from abc import ABC, abstractmethod

class BaseTranslator(ABC):
    @abstractmethod
    async def translate(self, text: str, source_lang: str, target_lang: str) -> str:
        """翻译单段文本"""
        ...

    @abstractmethod
    async def translate_batch(self, texts: list[str], source_lang: str, target_lang: str) -> list[str]:
        """批量翻译，默认逐段调用，子类可覆盖优化"""
        ...
Реализации:
`MockTranslator`: для разработки/тестирования, возвращает оригинальный текст с префиксом `[перевод]`
`GoogleTranslator`: вызывает API Google Translate
`DeepLTranslator`: вызывает API DeepL
Выбор осуществляется через конфигурацию `TRANSLATOR_PROVIDER`.
### 1.3 Поддерживаемые языки (Q-02 решение)
Первоначально поддерживаются: `zh` (китайский), `en` (английский), `ja` (японский), `ko` (корейский), `fr` (французский), `de` (немецкий), `es` (испанский), `ru` (русский).
Решение: исходный язык автоматически определяется (передается `auto`), целевой язык выбирается из указанного списка.

## 5. Реализация ключевого модуля
### 5.1 Получение содержимого из GitHub (соответствует FR-02)
**Модуль:** `app/services/github_service.py`
**Функциональность:**
Разбор URL ресурса, идентификация типа (issue / pull_request / readme).
Вызов API REST GitHub для получения содержимого.
Обработка ограничений скорости (обработка ответных заголовков `X-RateLimit-*`).
**Ключевое реализация:**
class GitHubService:
    def parse_url(self, url: str) -> dict:
        """解析 URL → {repo, type, number}"""
# Сопоставление путей issue / pull / blob/README и т.д.

    async def fetch_content(self, resource: dict) -> str:
        """根据资源类型调用对应 API，返回 Markdown 原文"""
        match resource["type"]:
            case "issue" | "pull_request":
                resp = await self.client.get(f"/repos/{repo}/issues/{number}")
                return resp.json()["body"] or ""
            case "readme":
                resp = await self.client.get(f"/repos/{repo}/readme")
                return base64.b64decode(resp.json()["content"]).decode("utf-8")

    async def post_pr_comment(self, repo: str, pr_number: int, body: str):
        """发布 PR 评论（FR-07）"""
Обработка ограничений скорости:
Без токена: 60 раз в час; с токеном: 5000 раз в час.
При достижении ограничения возвращается `403`, парсится `X-RateLimit-Reset` для расчета времени повторной попытки, автоматическое повторное выполнение не осуществляется.
### 5.2 Парсинг и разделение Markdown (соответствует FR-03)
**Модуль:** `app/services/parser_service.py`
**Предложение:** Используется `markdown-it-py` для парсинга Markdown в поток токенов, последовательный обход токенов для создания разделений.
**Правила разделения:**
| Тип токена | segment_type | translatable |
|---|---|---|
| heading_open + inline + heading_close | text | true |
| paragraph_open + inline + paragraph_close | text | true |
| inline в bullet_list / ordered_list | text | true |
| inline в table_cell | text | true |
| fence (кодовая блокировка) | code_block | false |
| code_inline | inline_code | false |
| link_open / link_close обернутый текст | link | true (только текст, URL оставляются без изменений) |
| image | link | false (URL оставляются без изменений) |
**Обработка комментариев в коде (внутри fence):**
def split_code_and_comments(code: str, lang: str) -> list[Segment]:
    """将代码块拆分为代码行(不可译)与注释行(可译)"""
    comment_patterns = {
        "python": [r"^\s*#"],
        "javascript": [r"^\s*//", r"^\s*/\*", r"^\s*\*"],
        "html": [r"^\s*<!--"],
        ...
    }
# Построчный анализ, комментарий → translatable=True, сохранение префикса комментария
**Стратегия регрессии:** В случае ошибки при парсинге, весь текст будет обработан как один `text` раздел, регистрируется лог ошибки.
### 5.3 Выполнение перевода (соответствует FR-04)
**Модуль:** `app/services/translator/`
**Процесс:**
Фильтруем фрагменты с `translatable=True`.
Параллельно вызываем переводчик (ограничивая количество параллельных запросов до 5 для предотвращения превышения лимитов службы перевода).
После получения перевода выполняем постобработку терминов.
Если перевод одного фрагмента не удался, это не останавливает процесс, и фрагмент помечается как `failed`.
**Постобработка терминов (FR-08):**
def apply_glossary(translated: str, source_lang: str, target_lang: str) -> str:
    """单词边界安全 + 最长匹配替换译文术语"""
    terms = glossary_repo.get_by_lang_pair(source_lang, target_lang)
# Сортируем термины по длине в порядке убывания (приоритет максимальному совпадению)
    terms.sort(key=lambda t: len(t.target_term), reverse=True)
    result = translated
    for term in terms:
# Используем границы слова `\b`, чтобы избежать замены внутри слов
        pattern = re.compile(r'\b' + re.escape(term.target_term) + r'\b')
        result = pattern.sub(term.target_term, result)  # 此处应为源→目标映射
    return result
**Примечание:** Словарь терминов содержит пары `source_term → target_term`. При постобработке в переводе (в целевой языке) ищутся несоответствующие формулировки, которые переводчик может предложить, и заменяются на стандартный `target_term`. Реализация должна поддерживать карту `target_term → стандартный термин` или заменять в переводе распространенные варианты `source_term`. Здесь предполагается, что в переводе встречаются распространенные варианты `target_term`, которые упрощаются до стандартного `target_term`.
**Перевод комментариев кода:** Извлекаем текст комментариев (удаляем символы) → переводим → восстанавливаем символы комментариев и отступы.
### 5.4 Сборка перевода (соответствует FR-05)
**Модуль:** `app/services/assembler_service.py`
**Логика:**
Сортируем все фрагменты по возрастанию `sequence`.
Для переведенных фрагментов использовать `translated_text` (в случае неудачи использовать оригинальный текст + `<!-- перевод не выполнен -->`).
Для непереведенных фрагментов использовать `source_text` и склеивать их без изменений.
Между фрагментами вставлять необходимые переносы строк в зависимости от типа (пустая строка между заголовками/параграфами, пустая строка перед и после блоков кода).
**Контрольный режим:** фронтенд отображает оригинальный и переведенный тексты рядом, не полагаясь на сервер для сборки.
### 5.5 Триггеры перевода (соответствующий FR-07)
**Модуль:** `app/routers/webhook.py` + `app/services/pr_service.py`
**Процесс:**
Вебхук получает события PR / комментариев.
Проверка подписи.
Определение перевода: событие PR: `action=opened` или `synchronize`, и настроено автоматическое переведение для этого репозитория.
Событие комментария: содержимое комментария начинается с `/translate`, анализируются параметры языка.
Создание задачи → асинхронное выполнение → после завершения перевода вызывается `post_pr_comment` для публикации.
Если для одного PR уже есть комментарий с переводом, обновляется комментарий (поиск комментария бота по `comment_id`).

| Тип ошибки | Обработка |
|---|---|
| Ошибка проверки ресурсов | Синхронный возврат 400, не создание задачи |
| Ошибка GitHub API 404 | Статус задачи → failed, сообщение "ресурс не существует" |
| Ошибка GitHub API 403 (лимит скорости) | Статус задачи → failed, возврат оставшегося количества запросов и времени повторной попытки |
| Ошибка сети GitHub API | Повторная попытка 1 раз, если неудачно → failed |
| Недоступность сервиса перевода | Статус задачи → failed, сообщение "сервис перевода недоступен" |
| Ошибка перевода одного фрагмента | Отметка о том, что этот фрагмент failed, продолжение с другими фрагментами |
| Уничтожение структуры кода в переводе | Отказ от перевода, сохранение оригинального текста, отметка об ошибке |
### 6.2 Стратегия повторных попыток
**Повторная попытка при извлечении данных:** повторная попытка при сетевых таймаутах 1 раз с интервалом в 2 секунды.
**Повторная попытка при переводе:** при失败单段不自动重试，由用户手动触发 `POST /retry`。
**Повторная попытка при ограничении скорости:** не автоматическая повторная попытка, пользователю рекомендуется повторить попытку после времени `X-RateLimit-Reset`.
### 6.3 Стандарты ответов ошибок
Все ответы ошибок имеют единый формат:
{
  "error": "错误代码",
  "message": "用户可读的错误说明",
  "detail": "可选：下一步操作建议或示例",
  "retry_after": 60  // 可选，秒
}
## 7. Безопасность и конфиденциальность
### 7.1 Границы данных
Только доступ к публичным ресурсам GitHub: перед вызовом API проверить поле `private` у репозитория на значение `false`.
Не хранить чувствительные凭据持久化：GitHub Token、翻译服务密钥仅从环境变量读取，不写入数据库。
Минимальное хранение: таблица задач содержит URL ресурса, исходный текст, переведенный текст, статус, информацию об ошибке.
### 7.2 Безопасность Webhook
Проверка подписи `X-Hub-Signature-256` с использованием HMAC-SHA256.
Проверка источника события как от GitHub (IP-белый список является опциональным).
### 7.3 Проверка входных данных
Формат URL ресурсов для валидации (регулярное выражение `github.com/{owner}/{repo}/...`)。
Целевой язык должен находиться в списке поддерживаемых。
Размер исходного содержимого ограничение: не более 1МБ на задачу (Q-04 решение)。
